SPECTER - PITCH AND REVENUE (short version)

THE PROBLEM
Most tools tell you a package was bad AFTER you installed it. By then the
malware is already on your machine.

OUR ANSWER
Check the npm package BEFORE it is installed. We give every package version a
verdict (allow / warn / block) and stop the install if it is bad.

WHAT WE HAVE TODAY (built)
- Scan any GitHub repo with 5 scanners (dependencies, secrets in commits,
  Docker, API routes, env files) and a 0-100 threat score
- 3D scene, AI explanation, PDF report
- Package risk signals from the npm registry (new maintainer, new dependency,
  install script, lost provenance, typosquat)
- Auto-monitoring of repos with Telegram alerts
- Demo scans of two real attacks (event-stream, node-ipc)

There is no login, payment, or API key system in the hackathon version.
The paid tiers are the business plan, shown on the pricing page.

WHY THE MONEY WORKS
- We check a package version once and share the answer with every customer,
  so extra customers cost us almost nothing.
- Expensive checks (sandbox, AI) only run on the few percent that look
  suspicious, so cost stays low.
- Customers pay for speed (verdict before anyone else), fewer false alarms,
  and enforcement (blocking), not for a plain lookup.

HONEST LIMITS
- A verdict is a risk signal, not a guarantee.
- Determined attackers can sometimes fool a sandbox, so it is one layer.
- A false alarm can break a build, so blocking is opt-in.
- Free tools exist (OpenSSF, GuardDog); we must win on speed and accuracy.
- npm only.
